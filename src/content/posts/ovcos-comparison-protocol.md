OVCOS 논문들을 나란히 놓을 때 먼저 필요한 것은 조건표다. 이 글은 **후속 리뷰와 실험을 위한 비교 설계 메모**이며, 아래 진단을 수행한 결과를 보고하는 글은 아니다.

## 같은 입력을 보고 있는가

클래스 이름만 받는 경우, 긴 설명을 받는 경우, 이미지에서 설명을 생성하는 경우를 구분한다. 추가 깊이 정보나 다른 모달리티를 사용한다면 별도 열로 남긴다.

| 항목 | 기록할 내용 |
| --- | --- |
| 데이터 | 데이터셋 버전, seen/unseen split, 제외 이미지 |
| 언어 입력 | 클래스 목록, 템플릿, 설명의 생성 방법 |
| 시각 입력 | 해상도, 크롭, 추가 모달리티 |
| 감독 | 마스크·클래스·점 주석, 보조 데이터 |
| 기반 모델 | 체크포인트, 고정·미세조정 범위 |
| 추론 | 호출 횟수, 후보 마스크 수, 재정렬 방식 |

OVCamo는 OVCOS를 위해 제시된 데이터셋이다. split과 평가 구현은 [저자 저장소](https://github.com/lartpang/OVCamo)를 기준으로 맞추고, 수정 사항은 결과와 함께 기록한다.

## 이름을 틀렸는가, 경계를 틀렸는가

두 종류의 oracle 진단을 제안한다. 이는 추가 분석이며 공식 벤치마크 결과를 대체하지 않는다.

- **정답 클래스를 제공한 분할:** 클래스 혼동을 제거했을 때 마스크 오류가 얼마나 남는가.
- **정답 마스크를 제공한 분류:** 위치를 정확히 알고도 어떤 클래스로 잘못 분류하는가.

두 진단 모두 test label을 사용하는 분석이므로, 일반 추론 성능과 같은 열에 놓지 않는다. 학습이나 하이퍼파라미터 선택에 이 결과를 사용하지 않는 것도 필요하다.

## 점수와 비용을 같이 보기

일반 OVS의 mIoU, OVCOS의 class-aware 지표, 인스턴스 분할의 AP는 서로 다른 평가 질문에 답한다. 분할 단위와 지표 정의가 일치하는 경우에만 직접 비교한다.

training-free 방법은 후속 작업의 학습 단계를 줄일 수 있지만, 설명 생성·기반 모델 호출·추론 보정의 비용은 남을 수 있다. 전처리 시간을 제외했는지, 캐시를 사용했는지, 이미지당 호출 수가 얼마인지까지 표에 적는다. 이는 [학습 없는 OVCOS 연구](https://openaccess.thecvf.com/content/CVPR2026/html/Ren_Training-Free_Open-Vocabulary_Camouflaged_Object_Segmentation_via_Fine-Grained_Object_Binding_and_CVPR_2026_paper.html)를 읽을 때 확인할 질문이다.

## 다음 비교에 넣을 세 가지

1. 같은 클래스 목록에서 동의어·설명 길이를 바꾼 민감도.
2. 객체 크기와 경계 복잡도별 오류 분포.
3. 백본·입력 해상도·추가 데이터·추론 예산을 맞춘 비교.

이 조건을 맞춘 뒤 의미 정렬, 구조 보정, 재정렬의 기여를 따로 읽는다. 관련 문헌은 [연구 지도](/research/?group=ovcos)에 연결해 두었다.
