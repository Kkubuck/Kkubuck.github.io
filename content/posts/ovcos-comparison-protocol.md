OVCOS 논문들을 나란히 놓으려면 먼저 조건표가 필요하다. 같은 OVCamo 점수라도 입력과 감독 조건이 다르면 직접 비교할 수 없기 때문이다. 이 글은 앞으로 리뷰와 실험을 할 때 쓰려고 정리한 **비교 설계 메모**이고, 아래 진단을 실제로 수행한 결과는 아니다.

## 같은 입력을 보고 있는가

언어 입력부터 다를 수 있다. 클래스 이름만 받는 방법, 긴 설명을 받는 방법, 이미지에서 설명을 생성해 쓰는 방법을 구분해야 한다. 깊이 같은 추가 모달리티를 쓴다면 따로 표시한다.

| 항목 | 기록할 내용 |
| --- | --- |
| 데이터 | 데이터셋 버전, 학습/평가 클래스 분할, 제외한 이미지 |
| 언어 입력 | 클래스 목록, 프롬프트 템플릿, 설명을 만든 방법 |
| 시각 입력 | 해상도, 크롭, 추가 모달리티 |
| 감독 | 마스크·클래스·점 주석, 보조 데이터 |
| 기반 모델 | 체크포인트, 고정한 부분과 미세조정한 부분 |
| 추론 | 기반 모델 호출 횟수, 마스크 후보 수, 재정렬 방식 |

OVCamo는 OVCOS를 위해 만든 데이터셋이다. 클래스 분할과 평가 구현은 [저자 저장소](https://github.com/lartpang/OVCamo)를 기준으로 맞추고, 바꾼 부분이 있으면 결과와 함께 적는다.

## 이름을 틀렸는가, 경계를 틀렸는가

OVCOS의 오류는 두 가지가 섞여 있다. 객체의 위치나 모양을 틀리는 **마스크 오류**와, 위치는 맞았지만 다른 클래스로 부르는 **분류 오류**다. 둘을 나눠 보기 위해 정답 정보를 하나씩 주는 진단(oracle)을 해 볼 수 있다.

- **정답 클래스를 주고 분할**: 클래스 혼동을 없앴을 때 마스크 오류가 얼마나 남는가.
- **정답 마스크를 주고 분류**: 위치를 정확히 알 때도 어떤 클래스로 잘못 분류하는가.

두 진단 모두 평가용 라벨을 쓰는 분석이므로, 일반 추론 성능과 같은 열에 놓으면 안 된다. 학습이나 하이퍼파라미터를 고르는 데 이 결과를 써서도 안 된다.

## 점수와 비용을 같이 보기

일반 개방 어휘 분할의 mIoU, OVCOS의 클래스 인식 지표, 인스턴스 분할의 AP는 서로 다른 질문에 답한다. 분할 단위와 지표 정의가 같을 때만 직접 비교한다.

학습이 필요 없는(training-free) 방법은 학습 단계를 줄여 주지만, 설명 생성이나 기반 모델 호출, 추론 중 보정에 드는 비용은 남는다. 전처리 시간을 뺐는지, 캐시를 썼는지, 이미지당 호출 수가 얼마인지까지 표에 적어야 공정하다. CVPR 2026의 [학습 없는 OVCOS 연구](https://openaccess.thecvf.com/content/CVPR2026/html/Ren_Training-Free_Open-Vocabulary_Camouflaged_Object_Segmentation_via_Fine-Grained_Object_Binding_and_CVPR_2026_paper.html)를 읽을 때 특히 확인할 부분이다.

## 다음 비교에 넣을 것

1. 같은 클래스 목록에서 동의어나 설명 길이를 바꿨을 때의 민감도
2. 객체 크기와 경계 복잡도에 따른 오류 분포
3. 백본, 입력 해상도, 추가 데이터, 추론 비용을 맞춘 비교

이 조건을 맞춘 다음에야 의미 정렬, 구조 보정, 재정렬이 각각 얼마나 기여하는지 따로 읽을 수 있다. 이어서 읽을 논문들은 [OVCOS 읽기 지도](/posts/ovcos-reading-map-2026/)에 정리했다.
